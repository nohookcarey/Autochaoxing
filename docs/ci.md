# GitHub 自动检查

正式配置：[teacher-assistant.yml](../.github/workflows/teacher-assistant.yml)。已从文档模板迁入工作流目录；是否启用及实际结论以[GitHub运行记录](https://github.com/nohookcarey/Autochaoxing/actions/workflows/teacher-assistant.yml)为准，不以文件存在宣称首轮通过。

## 触发与范围

- 主分支相关源码、文档、检查脚本、依赖配置及工作流发生变化时执行；PR同样触发。支持在Actions页面手动运行。
- Linux、Windows、macOS三组Node.js 22环境；执行仓库测试、隐私与导航路径检查、安装依赖、模块测试与构建、模块发布检查、官方源依赖审查、扩展构建和逐文件核验。
- 仅contents:read，不使用教师账号、API密钥或学生材料；不会登录学习通、写成绩、部署网站或自动发布Release。
- 执行器仅运行脱敏自动化及模拟材料，不等于指定浏览器扩展实机或两校真实教学验收。

同一分支的新提交会取消旧的尚未完成运行；跨平台采用明确的bash失败即停行为。依赖审查或测试失败时显示失败，不自动忽略或关闭告警。PR中的代码仍须维护者审查。

工作流修改需要GitHub客户端的workflow权限；账号授权、平台可用性和排队可能影响运行。不要将“已准备配置”“已提交工作流”“运行中”和“成功”混用。历史报告的CI模板状态保留为当时证据。

【知识库对齐核验】

- 引用依据：现有PRD、仓库目录/发布验收、自动沉淀规则与GitHub Actions官方说明。
- 锁定口径：最小权限、固定依赖与动作提交、脱敏测试、独立核对平台结果，不操作真实成绩。
- 变动警示：工作流由模板转为正式配置，首轮结果仍须平台实际运行；不扩大为跨校、浏览器或全场景验收。
